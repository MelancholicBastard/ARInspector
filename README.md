# AR Инспектор

Кросплатформенный Flutter-прототип помощника инженера по ТЗ КСТ ЭНЕРГО ИНЖИНИРИНГ.

Текущий этап: считывание QR-кодов оборудования. Камера открывается по кнопке,
распознаёт только QR, возвращает исходный текст и останавливается. Результат
можно выделить, скопировать и заменить повторным сканированием. Ссылки из QR
автоматически не открываются. Последний результат хранится до закрытия приложения.

Интерфейс на русском языке, Material 3 в стиле Expressive: крупная типографика,
скруглённые карточки, выразительные кнопки, заданная зелёная палитра и системная
светлая/тёмная тема.

## Запуск

Нужен Flutter с Dart 3.14 или новее.

```sh
flutter pub get
flutter run
```

Сканер mobile_scanner поддерживает Android, iOS, macOS и Web.
Разрешения камеры настроены для Android и Apple-платформ.
Для Web используйте HTTPS или localhost; браузер может загружать библиотеку
распознавания при первом запуске. На Android используется встроенная ML Kit,
поэтому распознавание не требует загрузки модели при первом использовании.
На Linux и Windows сканирование камерой пока недоступно.

## Проверки

```sh
flutter analyze
flutter test
flutter build apk --debug
```

Тесты проверяют QR-поток через подмену платформы камеры, повторные события,
пустые данные, повторное сканирование, отмену, жизненный цикл, отказ в доступе,
копирование и узкий экран с увеличенным шрифтом.

На реальном устройстве проверьте разрешение и отказ в доступе, распознавание
напечатанного QR, фонарик, сворачивание и повторное сканирование.
Сборка iOS/macOS требует macOS с Xcode.

## Навигация и настройки

Три вкладки: «Сканер», «Объекты», «Настройки». Считанный QR доступен во вкладке
объектов, но запись оборудования ещё не загружается. Камера открывается
отдельным маршрутом и освобождается при его закрытии.

Настройки сохраняются локально одним JSON-документом через flutter_secure_storage:
ФИО, должность, логин, пароль и URL сервера. На Android отключён Auto Backup,
для iOS настроен Keychain; macOS использует legacy Keychain без общей группы.
На Web требуется HTTPS или localhost. Сохранение не означает успешный вход
или проверку доступности сервера. Для удаления значений очистите поля и сохраните.

Сервер задаётся как базовый HTTP(S) URL (например, http://192.168.1.10:8000).
Строки подключения к PostgreSQL не используются в клиенте. Будущий API должен
искать equipment по qr_code, возвращать компоненты, параметры, измерения,
диагностику и историю обслуживания, а также авторизовать отправку отчётов.
В текущей схеме engineers не содержит учётных данных: серверу потребуется
связать пользователя с engineer_id. В приложении эта связь пока не имитируется.

## Осмотр с моделью

На вкладке «Сканер» кнопка «Осмотр с моделью» открывает отдельную камеру.
QR и осмотр работают отдельными сеансами, не захватывая камеру одновременно.
Задняя камера нужна для согласования ориентации кадра и рамок.
Режим поддерживает Android/iOS; Web использует периодические снимки, если
поток кадров недоступен. macOS/Windows/Linux пока поддерживают только
остальную часть интерфейса (QR на macOS по-прежнему доступен).

Примерный алгоритм:
- Около 5 раз в секунду сравнивается сетка яркости 24×24.
- Через 1 с без заметного изменения выбирается кадр, преобразуется в JPEG
  с длинной стороной до 640 px, без растяжения, с поворотом по ориентации.
- В каждый момент отправляется только один запрос. Пока модель отвечает
  (в том числе 2 с и дольше), сравнение кадров продолжается.
- При движении/смене ориентации/сворачивании приложения рамки и текущие
  результаты очищаются; ответ старого запроса отбрасывается.
- После ответа пауза не менее 500 мс; после ошибки — 3 с. Тайм-аут — 10 с,
  транспорт закрывается, рамки из ошибочного ответа не появляются.
- Кнопка списка вверху камеры открывает «Объекты». Там остаётся последний
  принятый результат с временем кадра, без имитации записи в БД.
  Новый осмотр или QR другой установки сбрасывает его.

Это эвристика стабильности изображения, а не трекинг SLAM: перемещения на
однотонном фоне могут остаться незамеченными, автоэкспозиция и движущиеся
объекты могут сбрасывать фиксацию. Пороги требуют проверки на реальной камере.
Рамки привязаны к изображению и удаляются при движении, а не отслеживают узел в 3D.
Низкая уверенность модели отображается как есть.

### Контракт API (пока предположение, сервер модели не предоставлен)

Базовый URL берётся из настроек. Пример: http://10.0.2.2:8000/api.
Запрос: POST /api/detect, multipart/form-data:
- image — JPEG, имя файла frame.jpg;
- width, height — размер отправленного изображения в пикселях.

Ответ: HTTP 200, UTF-8 text/plain, по одной строке на объект:

```text
pipe: 43.23% at [526.345345, 126.345453, 571.645751953125, 176.345435]
rust: 41.03% at [1.34564536, 109.345534, 378.345435, 254.345534]
```

Координаты — [xMin, yMin, xMax, yMax] в пикселях загруженного JPEG.
Сервер должен убрать собственные resize/letterbox-преобразования модели.
Пустой текст означает отсутствие найденных объектов; некорректный формат —
ошибку. Дробные координаты сохраняются, выход за границы обрезается.
Клиент не угадывает систему координат и не открывает произвольные ссылки.

Логин и пароль не отправляются: способ авторизации API ещё не определён.
HTTPS проверяет сертификат стандартно. Android разрешает HTTP только для
localhost и 10.0.2.2; другой HTTP-хост нужно явно добавить в
android/app/src/main/res/xml/network_security_config.xml и список в main.dart.
Общее разрешение HTTP отключено. Для iOS настроен доступ к локальной сети.
Web требует разрешения камеры, CORS на сервере и совместимой схемы HTTPS.

Проверки с подменой HTTP и управляемым временем покрывают медленный ответ,
один запрос в полёте, сброс при движении, игнорирование устаревшего ответа,
прекращение кадров, поворот/масштаб координат и обновление экрана объектов.
Для полноценной проверки нужны сервер модели и физический телефон.
